# preview.50 — source keys, fitting and constant cleanup

The user's exact Sonic AttackAirLw and previously retargeted Mario CHR0 files
were tested without modifying either input. Both source-key options were prepared
through the real native retarget action and its explicit motion review, fitted to
Mario Fall, then optimized as the exact current animation. The complete native
Model Previewer, original dense Next and native Undo remain intact. ONE G1/M2
milestone remains incomplete.

## Product changes

Authentic Sonic's donor CHR0 has native scaling-rule metadata 2. The source-key
snapshot path previously called a target-optimization metadata guard and rejected
that input. A separate internal donor snapshot now retains supported v4/v5 rules
0–2 through precise writing, independent reopening and stale-content checks. It
does not change the dense Next path, target writing or the existing rule-zero
target-optimization qualification boundary. Unknown modes still fail closed.
Managed snapshots retain their rule before their first rebuild; raw headers are
read using their own bounded version rather than a changed managed version.

Proved constant channels no longer retain redundant knots solely because fitting
joins exist. A single frame-zero key represents the same raw constant value and
positive-zero derivative at every join and subframe. Exact raw bind-equivalent
tracks can likewise use the native bind fallback after independent validation.
Paired sides, signed zero, nonzero tangents, authored protected intervals and
pin/contact structural dependencies remain protected. Neither quality limits nor
the source-owned motion policy were relaxed. Full composed certificates and
independent native encode/reopen/FK/skin checks remain mandatory.
