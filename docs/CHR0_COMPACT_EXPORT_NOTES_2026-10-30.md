unretargeted donor or a previously accepted approximate incumbent. The incumbent

## Native plan and verification

- `IndexedCHR0CurveStorage.CreateFloatDense` freezes physical binary32 samples
  in an immutable existing native L4 payload. It does not change the shared
  converter's codec heuristics or unrelated resources.
- `NativeCompactAnimationStorage.FloatDense.cs` admits nonloop v4/v5 whole-R
  proposals with legal fixed companions. Existing imported sampled data stays
  retention-only. Unknown paired sides, signed zeros, unsupported context,
  exact roots/pins/contacts/joins and exhausted budgets preserve their fallback.
- `NativeAnimationOptimization.FloatDense.cs` freezes every newly chosen whole-R
  payload plus complete explicit storage identity **before** serialization.
  Fresh decoding must retain those actual formats/bytes, even if the writer
  could otherwise fall back to motion-equivalent I12.
- Reopen, complete metadata/flags/timing, cumulative scalar/native geometry,
  applicable absolute fitting/contact admission and actual file/resource sizes
  remain acceptance gates. A smaller key count is not the cost function.

An N-frame nonloop proposal stores N+1 physical samples, with its last value
bit-identical to the preceding value. All bytes remain in the plan and output.
The current native reader exposes N samples. For the additional physical-linear
verification only, a freshly matched/accepted held L4 tail can be represented
as N keys plus the native constant clamp. This avoids comparing a manufactured
outgoing zero endpoint side with the reference's stored incoming side. The
original nonflat fixture and1e-8 limits stayed unchanged. The full physical
held interval is still checked; default/imported/L1/L2/loop/unheld cases and
authored extra endpoint sides receive no shortcut.
