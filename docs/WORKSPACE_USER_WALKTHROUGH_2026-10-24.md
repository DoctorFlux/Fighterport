# Workspace user walkthrough — prepared, not performed

Use the actual standalone Fighterport app, your own legally available fixtures
and a new output folder. A person operates the mouse/keyboard; no desktop-input
automation is needed. Keep original game files read-only. This checklist does
not claim first-time-user, physical-input, monitor-DPI or game acceptance.

## Tasks

| Case | User task | Expected result |
| --- | --- | --- |
| First supported transfer | Start a new project, add an original source model/motion pair, approve its association, select a clip, open an existing target, preview transfer | Ordinary workflow completes without expert settings; source and target remain visibly distinct |
| Native correction | Focus the editor, use original playback/frame shortcuts, edit a body bone, Undo/Redo and inspect curves | Complete native controls remain usable; protected motion/root controls cannot receive generated/manual corrections |
| Save and resume | Save the project, export the selected target animation to a new path, reopen both outputs | Correct independent target/clip is saved; reopening preserves supported authored data |
| Returning user | Reuse the same registered source on another independent target revision | No repeated source-model lookup or association approval for unchanged known inputs |
| Donor-free edit | Open a native target and its animation without choosing a library source | Native editing and save remain available without a donor wizard |
| Keyboard navigation | Use F6/Shift+F6, Tab/Shift+Tab, toolbar arrows and Enter/Space; open/close drawers and cancel dialogs | Focus is visible, focused actions scroll into view, drawers return to their invoker, native shortcuts and text editing retain their meanings |
| Unsaved recovery | Make an edit, choose New/Open/Close, try Keep editing and cancel the nested Save path; save successfully afterward | Existing work and Undo stay available; focus returns to the active decision/command; nothing is discarded implicitly |
| Readability | Repeat compact/wide layouts at 100% and 200% workspace text on the current monitor | Essential commands and primary action remain reachable; no document changes result from resizing/navigation |

For the keyboard case, F6 visits project commands, workspace actions, stages,
visible library/tasks and the full native editor. Hidden/disabled regions are
skipped. The task starts at its primary action. Library Tab order begins Search,
Clear, source tree, then its other controls. Escape closes a pane only while focus
is inside it; native gesture cancellation and modal decisions retain their roles.

## Record observations

For each task, record build/commit, monitor/OS scale, workspace text size, window
size, fixture/operation, completion or blockage, command activations, repeated
setup prompts, hidden-command searches, wrong-document mistakes and assistance.
Keep private fixture paths and screenshots out of public source.

Pass the bounded supported-flow walkthrough only when the tasks complete with
zero wrong-document saves/exports or lost edits; unchanged known sources need no
repeat association; ordinary transfer needs no expert settings; keyboard focus
remains recoverable and all original native editing controls remain usable.
Record navigation friction for follow-up rather than invent a human baseline or
claim measured improvement from automated handler counts.

Batch, model-port, foreign-game destinations, physical/mixed-monitor DPI, broad
motion/contact quality and actual game testing need their own cases and evidence.
This walkthrough does not close those gates or all of G1/M2.
