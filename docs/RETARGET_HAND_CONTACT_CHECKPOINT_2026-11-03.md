## Demonstrated cause and bounded correction

The original coupled body-contact solver used a target **leg** threshold, `0.005 × leg length`, to stop full-support end-contact fitting. For a Snake `DownStandU` transfer onto Mario, a source-derived right-hand support proposal at native frame **4.125** remained **−0.0065509453** units in the solved pose; a freshly reopened CHR0 measured **−0.0065497830**, and independent MDL0 skinned vertices measured **−0.0065497533**. Mario's right arm length is **3.4765923**, so the existing `0.001 × arm length` position bound is **0.0034765925**. The discrepancy began before CHR0 encoding. The source-derived hand proposal is not proof of a verified game floor.

`BodyContactSolver` now reserves each full-support hand/foot contact against its own arm/leg length and cannot stop on the old leg-scaled end threshold, including the general-precision early exit. Its lock drift reserve is no looser than the earlier leg-scaled rule. The existing cancellation token now interrupts the bounded inner solve. The change does not modify source-owned root controls, target skeleton, binds or skin weights. The same transfer's old frame-4.125 depth is effectively zero after the change; its worst withheld full-support eighth-frame depth is **−0.001483582** at frame **5.375**, below the unchanged bound. Fresh native MDL0 skin independently measured about **−0.001484416** there. The corrected result is **189,368 bytes**, versus the former **178,436 bytes**, and used **3,980** body-solver iterations. Motion quality took priority over this size and work increase; performance remains open.
