# Target profiles and complete-character roadmap

Read-only game-source profiles now support updating a selected installation/disc/tool path without changing that profile's ID; Save as new build retains separate named Project M/Project+ profiles. Brawl-family extracted asset/SD/install folders and selected WBFS/ISO DATA packages have a bounded browser/preparer (`GAME_SOURCES.md`). Source registrations stay global/local and distinct from authored target configuration, native packaging, deployment and game testing. Other registered games still require their own native source adapters. No complete builder is enabled by this intake path.

Schema-2 character projects now store multiple stable named target configurations and independent scene documents, demonstrated with Project+ Main, Project+ Practice and an unresolved Rivals II configuration. Shared scene assignment creates a separate authored copy; local keys/history/settings/gameplay/media do not alias another target. Configuration records retain game/platform/build/mode and optional framework/template revisions. Existing schema-1 target metadata does not prove scene ownership and requires explicit assignment after upgrade. These are authoring/configuration capabilities, not complete native builders. External native workspace leases/deployment overlap checks and target-native build orchestration remain open; managed output guards reject other targets' folders. See `CHARACTER_STORAGE.md`.

Each versioned target identifies game, platform, build/framework revisions and replacement/expansion mode. Separate Brawl, configured Project M, Project+, Melee/m-ex, Ultimate replacement, Ultimate Clone Engine expansion and Rivals II. Do not assume a universal numeric slot. Wii U, 3DS and Smash 64 have distinct planned adapters. Xenoverse 1/2, FighterZ and Sparking! ZERO are separate donor-source adapters; Rivals 1 retains a separate 2D sprite/GML workflow.

Required/optional/alias/legitimate fallback slot manifests come from actual native definitions or installed SDK schemas. Protected assignments survive Auto Fill. Rank reviewed mappings and compatible semantic candidates; retarget, fit and validate before assigning, with one batch undo and explicit unresolved roles. Never fill arbitrary gaps with Idle.

Complete-character readiness includes geometry/rig/material/weights/morph/helpers, true outfit variants separately from palettes, gameplay/hitboxes/hurtboxes/scripts, audio/banks, VFX/props, CSPs/BPs/stock/HUD/results artwork and per-target dependency/build/install rollback receipts. Conditional articles, Kirby copies, transformations, partners, Final Smash and ending assets need supported output, declared valid fallback or explicit N/A. A motion assignment does not complete gameplay.

Builders: BrawlInstaller-compatible packages after verification; Melee v1.02/m-ex and mexTool with pinned licenses; Ultimate ARCropolis replacement and separately experimental Clone Engine/Workbench; Rivals II installed official Modkit. No adapter is verified by configuration alone.
