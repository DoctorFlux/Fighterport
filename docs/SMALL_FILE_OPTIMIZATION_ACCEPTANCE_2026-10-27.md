# Small file optimization acceptance — 27 October 2026

**Qualified: 5,682 application/Core checks across 11 runs, 30 inspected native PNGs, six GIFs covering 332 decoded frames, and a separate 20-file byte audit.**

Animation → Optimize animation. Exact remains the default and existing High

## Authority and limits

The user explicitly approved an additional profile with 0.1° raw Euler and local
orientation error, 0.002 native-unit local translation vector error and 0.0001
scale-component error. Derivatives retain ceilings of 0.1°/native frame,
0.002/native frame and 0.0001/native frame respectively. Cumulative native
hierarchy/basis and skinned-position differences, and sampled error-chord
derivatives, must stay within 0.001 times the authentic bind-geometry diagonal L.
Without a valid positive L and reviewed motion-control context, approximation
remains unavailable.

Fitting joins retain their timing/sides or a proved equivalent fixed
representation; numeric join values/tangents may change within Small bounds.
Explicit mandatory points/ranges, source-owned motion and authored pin/contact
dependency closures keep exact protections. Paired keys, authored signed zeros,
singular/sign-changing scales, full unwrapped turns, timing and native flags keep
their existing policies. No role or target membership is inferred from a name.

## Implementation

Core adds a separate SmallFile mode and separate FitJoinFrames input. Existing
MandatoryFrames never changes meaning. Hermite reductions retain rational
value/derivative certificates and the existing two-million-work/100,000-span
limits. Native cumulative validation retains the existing witness/bone/skin
budgets; exhausted or rejected work can return only a previously verified result
or unchanged data.

Optional indexed I4/I6 storage supplements minimum-anchored grids with a
zero-aligned grid for Small. Only non-exact body rotation/translation coefficients
may round a tiny nonzero value/tangent to +0 within the selected profile. Authored
+0/-0, paired/mandatory/protected coefficients and scale retain their guards.
The old Exact/High-quality overload has the same candidate order and zero policy.
Complete decoded candidates still require retained-original continuous scalar
certificates and independent native pose/mesh validation; local knot checks are
proposal filters rather than sufficient acceptance.

The dialog locks the selected profile during work and includes it in prepared
and cached identities. Switching Small to High quality uses the retained original
session baseline and cannot silently certify an approximate result against itself.
Analyze/cancel is read-only; Apply uses one existing native command on the same
member, preserving target, animation identity, selected bone, frame, camera and
sibling resources. Save/export/reopen and historical retarget/fit recipes retain
their established ownership. No automatic optimization or schema migration is
introduced.

## Reproduction and boundaries

Build the native app with scripts/Build.ps1 -NativeOnly, publish the owned engine
with scripts/Build-Engine.ps1 using the local .NET10 SDK, then build
tests/ControlsAcceptance in Release/x86 with BuildProjectReferences=false into
the frozen package. Build Core tests from engine's SDK directory, copy the
packaged Core/adapter DLLs into the isolated runner, and use
--animation-optimization. RetargetAcceptance --motion-controls runs both root
directions without a renderer. Full exact commands, fixture hashes, private
desktop requests and receipts are retained beside each local artifact case.

Small is a controlled quality tradeoff, not a universal file-size promise. The
stored Sonic source, native precise re-encoding, source-key preparation, fitting
and optimization bytes must be reported separately. PAC/container savings require
independent measurement. Continuous scalar bounds and sampled native geometry
results are different claims; sampled geometry is not a proof of all-time
contact quality. Physical input, monitor DPI, human usability, universal contacts,
Melee/new game adapters and actual game acceptance remain unverified. Source-only
publication uses DoctorFlux attribution on public Fighterport/main; private game
assets/settings, captures and generated binaries remain excluded.
