## Implemented boundary

Retarget source-bone/source-channel/interpolated preparation now calls the same
native indexed packing search as the explicit optimizer after its precise
candidate qualifies. The immutable finished Dense TARGET remains the motion
reference; the precise prepared candidate supplies the additional physical-byte
ceiling. The donor's different motion/model is never a compression reference.
Six packing attempts share the existing scalar and native budgets; the explicit
optimizer retains its 24-attempt ceiling. Search effort grants no extra error.

Retarget ceilings remain 0.01° raw Euler/local orientation, 0.00001 scale,
min(0.0002 native units, 0.0001 × L) local translation and 0.0001 × L native
world/basis/skin distance. Derivatives remain 0.05° per native frame for Euler
and the corresponding component limits per frame. `L` is the frozen positive
bind-geometry diagonal. Existing 2M scalar-work / 100k spans and shared native
100k witnesses / 10M bone visits / 1B skin-vertex visits remain. The explicit
optimizer retains its separately saved Exact/error-bounded policy and limits.

Every proposed complete file is serialized and freshly decoded before acceptance.
Exact I4/I6 choices retain all time/value/tangent bits. Bounded choices require
continuous rational Bernstein value/derivative bounds and cumulative native
local/orientation/hierarchy/all-skin checks against the same finished target.
Protected controls remain exact. Unknown paired sides, signed zeros, jumps,
mandatory boundaries and singular/sign-changing scale retain their contracts.
Nonconstant looping channels conservatively retain precise coefficients when
their complete native wrap cannot be certified. Source markers remain seeds;
quality-required additional target keys are preserved.

Reviewed generated-pair permission is separate from SmallFile/positive-zero
permission. It admits proposals only at unique exact bone/channel/time claims
with actual finite continuous ordered sides. Final scalar/native checks still
decide acceptance. Unreviewed SmallFile pairs now remain exact as well.

Fitting snapshots preserve imported storage before editing. After its numerical
result qualifies, a shared storage-only helper may choose smaller exact I4/I6
groups; it must preserve full coefficients, flags, metadata and complete terminal
payloads through a real write/reopen. A failed/no-saving proposal retains the
verified reference. Fitting's master and joins receive no new approximation.

Qualification also exposed a separate preview-stage payload loss: exporting the
live motion root to create preview context discarded imported storage and cleared
the selected clip's dirty flag. Numeric content remained unchanged, but its
serialized hash changed and the correct stale guard rejected the next fit.
Preview context now uses raw stream copies of ARC/BRRES containers and a fresh
selected MDL0 snapshot in independent owners. Pure-motion references are omitted;
current CHR0s are posed separately. Exact visual paths, native ancestor/ARC
metadata and untouched visual bytes must match. Dirty textures/palettes,
additional-model edits, unsupported/rawless or changed visual structures fail
closed with an explicit save-context message. The helper limits each context
to 512 MiB, 100,000 visited nodes and 128 levels, with cancellation; it adds no
new animation/solver budget. This boundary preserves authored animation storage,
dirty/backing state and native texture/palette lookup without a new renderer.

Ordinary right-click Export keeps preview.60's unchanged native picker and writes
the current animation without optimization analysis. Exact ordinary Save,
original Next, complete native viewer, all weights, source assets, historical
recipes and native Undo remain. No project-format, renderer or game-adapter
change is included. The new files do not modify the shared BrawlLib codec.

## Measured files

The [independent byte audit and benchmark](CHR0_PAYLOAD_NOTES_2026-10-29.md)
separates the supplied source/target diagnosis from like-for-like finished-target
comparisons. Both a Python decoder and the pure C# byte accountant agree across
26 old/new paths. The supplied 12,016-byte Sonic and 83,864-byte Mario originals
remain unchanged. An identical visible key schedule does not imply an identical
payload: HipN X uses 53 source L1 bytes versus 896 target I12 bytes, including
paired tangent rows.

The actual UI case measures **83,864 → 81,140 bytes** with the same 6,912 native
keys. Direct Sonic → Mario bone-key output measures 135,468 → 99,172 with identical
decoded tuples and 13,558 keys; its channel-key output measures 74,060 → 69,848
with bounded coefficient changes and the same 6,095 keys. Reverse channel and
Interpolated results measure 111,320 → 108,616 and 99,572 → 96,868 with identical
old/new tuples. Reverse bone and forward Interpolated retain their existing
qualified files. These results are bounded-search outcomes, not global optima
or promised compression percentages. No PAC/container saving was measured.

## Remaining boundaries

Continuous scalar certificates and sampled native geometry are different evidence.
Finite skin/contact samples do not prove continuous geometry or universal contact
quality. Existing unresolved quality gates remain. Unsaved texture/palette and
structural visual-context editing are outside the new raw snapshot boundary;
save them before fitting. New lossy looping/wrap storage,
broader codec/timing search and global size optimality are not claimed. Melee,
external editors/plugins, physical input/pickers, monitor DPI, human usability,
general contacts and actual game acceptance remain unverified. Existing compact
viewport/tree clipping and larger-text scrolling remain documented observations;
the viewer was not redesigned.
